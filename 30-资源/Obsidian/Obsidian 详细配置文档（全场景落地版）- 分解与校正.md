# Obsidian 详细配置文档（全场景落地版）｜分解与校正

> [!summary] 总结

## 二、值得保留的原则

1. **本地优先**：Markdown 文件由用户掌控，不被单一平台锁定。
2. **轻量化优先**：先用核心功能，遇到真实痛点再增加社区插件。
3. **附件集中管理**：避免图片和 PDF 散落在仓库根目录。
4. **模板统一格式**：会议、项目、学习和每日记录保持一致结构。
5. **文件夹不宜过深**：最多约三层，配合搜索和双向链接使用。
6. **社区插件控制数量**：插件越多，兼容、安全和维护成本越高。
7. **同步不等于备份**：应保留独立、可恢复、带版本的副本。

## 三、必须校正的内容

### 3.1 功能和设置错误

| PDF 说法 | 问题 | 正确处理 |
| --- | --- | --- |
| 设置 → 安全 → 仓库加密，可为本地仓库设置密码 | Obsidian 没有这一项本地 Vault 密码功能 | Obsidian Sync 的远程仓库支持端到端加密，但官方明确说明**不会加密本地 Vault**；本地敏感数据应使用系统磁盘加密或加密容器 |
| 关闭“允许匿名数据收集”“允许发送错误日志” | 当前 Obsidian 并不存在文档描述的这组开关 | 官方隐私政策说明 Obsidian 不收集遥测数据，无需寻找虚构开关 |
| 开启“定期备份提醒” | 不是标准全局设置 | 使用系统计划任务、备份软件或日历提醒；File Recovery 只用于短期恢复，不是完整备份 |
| 全局新建笔记使用当前日期作为文件名 | 普通新建笔记没有这项通用开关 | Daily Notes 默认按日期创建；Unique Note Creator 可创建时间编码标题 |
| “剪贴板”“任务清单”是核心插件 | 当前核心插件列表没有这两个插件 | 粘贴附件属于内置编辑能力；`- [ ]` 是原生 Markdown 任务语法，复杂任务管理需按需选社区插件 |
| 关闭附件随机文件名 | 当前文件与链接设置没有文档描述的标准开关 | 重点设置“新附件的默认位置”，附件重命名另行处理 |
| 路径必须纯英文、无空格、无中文 | 不是 Obsidian 的硬性要求 | 中文和空格通常可用；跨脚本、Git 或第三方工具时，简洁路径更省心，但不应写成强制规则 |
| Linux 安装统一把可执行文件放入 `/usr/local/bin` | 过度简化不同发行版的安装方式 | 按官方安装包和发行版方式执行，不要把单一路径写成通用步骤 |

### 3.2 插件名称与定位问题

对照当前 Obsidian 官方社区插件注册表：

| PDF 插件 | 当前注册表 | 建议 |
| --- | --- | --- |
| Advanced Tables | 存在 | 仅在频繁编辑复杂 Markdown 表格时安装，不属于所有人必装 |
| QuickAdd | 存在 | 有大量快速捕捉流程时再装 |
| Templater | 存在 | 需要脚本、条件或高级变量时使用；普通模板先用核心 Templates |
| File Explorer Enhancements | **未找到同名插件** | 不要按 PDF 名称搜索安装，先明确具体需求再找替代品 |
| Backlinker | **未找到同名插件** | 先使用核心 Backlinks 和 Outgoing Links |
| Search Everything | **未找到同名插件** | 先使用核心 Search；需要 PDF/OCR 等扩展搜索时再选择当前仍维护的插件 |
| Style Settings | 存在 | 只有当前主题声明了相应配置项时才有意义 |
| Iconize | 存在 | 纯视觉增强，可不装 |
| Kanban | 存在 | 项目确实适合看板时安装；也可先评估核心 Bases |
| Excalidraw | 存在 | 需要手绘图和视觉思考时安装 |
| Auto Note Mover | 存在 | 自动移动文件可能改变链接与目录，建议先小范围测试 |
| Smart Connections | 存在 | 并非只能绑定 OpenAI；模型和隐私取决于实际配置 |
| Copilot | 存在 | 会与现有 AI 助手功能重叠，避免重复安装 |
| Local AI for your vault | 存在 | PDF 把 Gemini 写成本地模型不准确；Gemini 通常是云端服务，本地应核对插件支持的模型与运行时 |

> [!warning] 社区插件安全
> 社区插件会在本机执行第三方代码。不要只看下载量；还应检查维护状态、源码、权限、网络访问和数据去向。

### 3.3 主题与 CSS 问题

1. **Minimal 是主题，不是社区插件**。正确入口是“设置 → 外观 → 主题 → 管理”。
2. 文档中的 `.theme-dark body` 很可能匹配不到正确节点，应按当前 DOM 使用 `.theme-dark` 或 `body.theme-dark`，并先在开发者工具中验证。
3. `.sidebar`、`.button` 等选择器不是可靠的 Obsidian 通用接口，版本或主题变化后容易失效。
4. `.workspace-split { gap: 4px; }` 可能破坏工作区布局，不应标注为“直接复制、无需修改”。
5. `.status-bar-item:not(.status-bar-clock)` 会隐藏所有不带该类的状态栏项目，而默认 Obsidian 并没有必须存在的 `status-bar-clock`。
6. CSS 同时强改主题颜色变量，可能覆盖主题自身的配色和可访问性设置。

**结论：** 不要直接启用 PDF 的整段 CSS。先使用默认主题；确有视觉需求时，一次只添加一条规则并验证浅色、深色和移动端。

### 3.4 文件夹结构问题

PDF 给出的结构偏向“公司办公资料归档”，会把同一个主题拆到工作、知识、素材、任务多个位置。对个人长期知识库，更适合按内容状态和用途组织。

你当前已经采用：

- [[00-收件箱/收件箱|收件箱]]
- [[10-项目/项目索引|项目]]
- [[20-领域/领域索引|领域]]
- [[30-资源/资源索引|资源]]
- [[40-归档/归档索引|归档]]
- [[90-模板/模板索引|模板]]

这套结构比 PDF 的工作型目录更通用。**不要再平行创建 `01_工作笔记`、`02_知识沉淀` 等第二套根目录**，否则分类标准会相互冲突。

## 四、结合当前仓库的配置审计

### 已有状态

- 核心插件已开启：文件管理器、搜索、反向链接、图谱、Canvas、Properties、Daily Notes、Templates、Outline、File Recovery、Sync、Bases 等。
- 社区插件目前只有 `realclaudian`，整体非常轻量。
- `app.json` 和 `appearance.json` 仍为默认空配置。
- 已有三套模板：[[90-模板/知识笔记模板]]、[[90-模板/项目模板]]、[[90-模板/每日笔记模板]]。

### 当前最重要的问题

> [!danger] 磁盘空间
> 检查时 C 盘可用空间显示为 **0 GB**，而当前 Vault 位于 C 盘。磁盘空间不足会影响 Obsidian 保存、索引、插件更新和系统稳定性。这比主题或插件配置更优先：应先释放空间，并把 Vault 备份到另一块物理磁盘或可靠的版本化备份位置。

## 五、推荐落地顺序

### 阶段 A：只用核心功能

- [ ] 释放 C 盘空间，确认笔记可以正常保存。
- [ ] 为整个 Vault 建立独立备份；不要把 Sync 或 File Recovery 当作唯一备份。
- [ ] 将核心 Templates 的模板目录设置为 `90-模板`。
- [ ] 新建 `99-附件`，将“新附件的默认位置”设置为该目录。
- [ ] 如需每日记录，新建 `05-每日笔记`，并将 Daily Notes 模板指向 `90-模板/每日笔记模板`。
- [ ] 保持默认主题一周，先验证真实工作流，再决定是否更换主题。
- [ ] 保留 File Recovery，并检查快照保留时间。

### 阶段 B：出现真实痛点后再装插件

| 痛点 | 首选方案 |
| --- | --- |
| 模板只需日期、时间、标题 | 核心 Templates |
| 模板需要条件、脚本、自动套用 | Templater |
| 捕捉步骤太多 | QuickAdd |
| 大量复杂表格编辑困难 | Advanced Tables |
| 需要任务看板 | 先试 Bases，再评估 Kanban |
| 需要手绘图、流程图 | Excalidraw |
| 需要主题参数调整 | 主题确认支持后再装 Style Settings |

### 阶段 C：AI 与自动化

- 当前已有 Claudian，可先用它完成整理、摘要、链接和 Vault 管理。
- 不建议同时安装多个 AI 插件，以免重复索引、重复付费和扩大 API Key 暴露面。
- 自动移动笔记前先备份，并在小目录中测试规则。
- 涉及工作机密时，逐项确认插件是否联网、内容会发送到哪里、由谁保存。

## 六、建议的最终配置

### 核心插件保留

- 文件管理器、搜索、快速切换、反向链接、出链、大纲
- Properties、Templates、Daily Notes
- File Recovery
- Bases（需要结构化视图时）

### 按需开启

- Graph：探索链接时使用，不必常驻侧栏
- Canvas：需要空间化整理时使用
- Sync：已购买并完成远程 Vault 配置时使用
- Slides、Audio Recorder、Publish：无需求则关闭

### 社区插件上限

不设机械的“必须少于 10 个”，但每个插件都应能回答三个问题：

1. 它解决了哪个持续出现的痛点？
2. 核心功能是否已经能完成 80%？
3. 停止维护后，笔记内容是否仍可正常读取？

| 维度 | 评价 |
| --- | --- |
