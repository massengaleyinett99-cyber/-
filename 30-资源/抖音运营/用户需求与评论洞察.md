# 用户需求与评论洞察

## 第一轮结论

下列问题在 10 条代表样本的可见评论中反复出现。这里是定性研究，不把可见评论误当成全平台统计。

## 评论证据表

| 需求／评论语言 | 证据强度 | 对应样本 | 可转化内容 |
| --- | --- | --- | --- |
| “怎么安装”“求安装包”“卡在登录” | 很强 | S01、S04、S07、S08 | 安装清单＋登录排查，不承诺远程安装 |
| 是否要 GPT 账号、海外手机号、特殊网络 | 很强 | S01、S04、S07、S10 | 先列前置条件和合规边界 |
| “免费吗”“一个月多少钱”“Token 烧得快吗” | 很强 | S01、S03、S04、S05、S09、S10 | 单任务成本实测＋余额提醒 |
| Computer Use 灰色、缺失或无法控制 | 很强 | S03、S05、S07 | 三步排查＋成功判断标准 |
| 接国产模型后是不是“阉割版” | 强 | S02、S03、S06、S09 | 原生能力与模型能力对照实测 |

| Obsidian、PPT、视频剪辑等具体场景 | 中等 | S05、S06 | 按场景拆成系列内容 |

## 用户心理

1. **想降低门槛：** 不想处理账号、环境和复杂命令。
2. **怕花冤枉钱：** 对订阅、API 与 Token 缺少成本预期。
3. **怕装成阉割版：** 能聊天不等于能用插件和 Computer Use。
4. **怕教程过期：** 软件更新后旧步骤很容易失效。
5. **想先看结果：** 只有看到真实控制或成果，才愿意继续学配置。

## 内容回应原则

- 开头 8 秒内给出成功证据。
- 步骤前先写明版本、系统、账号和费用条件。
- 同时给出“成功标准”和“失败排查”，而不是只展示顺利路径。
- 资源 CTA 提供清单与链接，不诱导用户把账号或电脑权限交给陌生人。
